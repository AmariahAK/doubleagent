## 1. Source and evidence level

Closed source (`github/copilot-cli` repo is issues only). Evidence is the **shipped bundle**: `npm pack @github/copilot` 1.0.91 (5 KB loader, `buildMetadata.gitCommit 216810c5`) → `npm pack @github/copilot-linux-x64@1.0.91`, a 178 MB Node single-executable (`copilot`). Its SEA blob (magic 0x143da20 at 0x67a01b8) holds `sea-loader.js` (122 KB, `scratchpad/npm/cp-sea-loader.js`) and one asset `copilot.tgz` (69.7 MB, `scratchpad/npm/cp-asset-copilot.tgz`), extracted to `scratchpad/npm/cp-pkg/package/`: `app.js` (7.6 MB JS), `prebuilds/linux-x64/cli-native.node` (8 MB) and `runtime.node` (122 MB, Rust). Citations: "app.js" with the surrounding identifiers, "sea-loader" (same code appears in cc-loader), "native"/"runtime" for byte-string hits. **Docs**: [Copilot CLI configuration directory reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference). **Local**: names-only listing of `~/.copilot` and `~/.cache/copilot`.

The 1.0.98 bundle (`@github/copilot-darwin-arm64`, loader `buildMetadata.gitCommit` `45ef16251c8`, `copilot` sha256 `b1a76d9eec3c88e8545ee96834189ab08c3d75ef65500a60925187fa6c33fdf1`) has the same SEA (Node single executable application) layout with one extra byte after the blob flags (magic at `0x5888000`, `copilot.tgz` at `0x58a6877`); `app.js` is now a 42 KB bootstrap and the CLI code is `cli-main.js` (sha256 `151c2e2a37ddb2514fc5cdbd5c473f9aeeb1a74d59e5062f3921a46d12a8f1c2`), with the state paths in the Rust addon `prebuilds/darwin-arm64/runtime.node`. Citations to it are written `cli-main.js@<byte offset>` or `runtime.node@<byte offset>` with a snippet; the extraction is described in [section 1 of `analyzer/research/copilot-cli.md`](../../analyzer/research/copilot-cli.md#1-evidence).

- **Observed (macOS)**: Copilot CLI 1.0.98 installed with Homebrew's npm, the author's workstation, 2026-10-15, surveyed for names, sizes, key names and types only (three interactive sessions). `~/.copilot` held `command-history-state.json`, `config.json` (JSONC, JSON with comments: one or two `//` comment lines before plain JSON, so a strict JSON parser refuses it; [section 2](#2-per-user-storage)), empty `ide/`, `installed-plugins/`, `servers/` and an empty `installed-plugins.lock`, `logs/process-<epoch ms>-<pid>.log` and `.copilot-log.lock`, `open-sessions-state.json` (`{}`), `permissions-config.json`, `session-state/` (`.session-operation-locks/<uuid>.lock` and one directory per session), `session-store.db` with `-wal` (1.7 MB) and `-shm` (the main file 4 KB), `settings.json` and `sidebar-sessions-state/<sha256 of cwd>.json`. Each session directory held `events.jsonl`, `workspace.yaml`, `.workspace-fork.lock`, `checkpoints/index.md`, empty `files/` and `research/`, and `rewind-file-snapshots/` (`index.json`, `tracking.json`). No `~/.config/.copilot`, `~/.local/state/.copilot` or `~/.cache/copilot`. `~/Library/Caches/copilot` held `copilot-user-cache.json` and `exp-cache.json` (both JSONC) with `.lock` files, `managed-settings/<hex>.json` with `managed-settings.<hex>.order.json` and a lock, `marketplaces/.auto-update.lock`, `memory-enablement-cache-config.json`, and the extracted package `pkg/darwin-arm64/1.0.98/` (with `.extraction-complete`).
- **Observed (Linux)**: Copilot CLI 1.0.98 installed with `sudo npm install -g @github/copilot`, an Ubuntu 26.04.1 arm64 Parallels VM (kernel 7.0.0-38-generic, `/bin/sh` dash, home `/home/sean`), 2026-10-16, surveyed for names, sizes, key names and types only. Exercised: `copilot login`, then two interactive sessions, the first in `~/demo` (created 21:01:19Z, shut down 21:16:01Z, UTC) and the second in `~/secret` (21:16:26Z to 21:19:27Z), after which the user removed the project with `rm -r secret/`. Every action ran before the first listing, so no per-action listing diff exists; the times above and the files' modification times are the only mapping from action to file. `~/.copilot` held the macOS set above except `settings.json`, which was not written: three `logs/process-*.log` (105 bytes for `copilot login`, 16 KB and 15 KB for the sessions), `session-store.db` (4096 bytes) with a 1.37 MB `-wal` and `-shm`, and two `sidebar-sessions-state/` files, one for the removed `~/secret`. No `~/.config/.copilot` or `~/.local/state/.copilot`. `~/.cache/copilot` held the names macOS keeps in `~/Library/Caches/copilot`, with the package under `pkg/linux-arm64/1.0.98/` (`.extraction-complete`, `cli-main.js`, `prebuilds/linux-arm64/runtime.node`, `schemas/`). The login put the GitHub token in the GNOME keyring (the GNOME desktop's password store, which the runtime reaches through its vendored Secret Service client), not in `config.json` ([section 3](#3-credentials)); the first session start wrote one file outside the catalog ([section 2](#2-per-user-storage)). The x64 GitHub Copilot Desktop AppImage, launched by mistake on the arm64 VM, failed to start and wrote nothing under `~/.copilot` ([issue 147](https://github.com/seanthegeek/doubleagent/issues/147) tracks the desktop app). Collector 1.13.0, run as the user (not root): 38 files collected, 2 `skipped_excluded` (`.copilot/installed-plugins`, `.cache/copilot/pkg`), 1 `secret: true` (`.copilot/config.json`), 0 `skipped_secret`, and 5 `error_read` rows on other accounts' homes (permission denied, expected without root); project discovery found `/home/sean/demo` from `workspace.yaml`. Windows was not observed on 1.0.98.

## 2. Per-user storage

Config home: `configDir ?? process.env.COPILOT_HOME ?? join(homedir(), ".copilot")` (app.js `function dot(e)`, `dQe`; native: "Set the configuration directory (default: ~/.copilot). Deprecated: use COPILOT_HOME env var instead"). Same on all OSes; docs confirm `~/.copilot` and `COPILOT_HOME`.

XDG handling: on start the CLI *migrates* state out of XDG dirs into `~/.copilot` (app.js `function CEn(e,t)`): from `$XDG_STATE_HOME/.copilot/` the entries `session-state`, `session-store.db`, `command-history-state`, `command-history-state.json`, `installed-plugins`; from `$XDG_CONFIG_HOME/.copilot/` the entries `config.json`, `config`, `mcp-config`, `lsp-config`, `permissions-config`, `copilot-instructions.md`, `mcp-oauth-config`, `hooks`. So older installs with XDG set may still have `$XDG_STATE_HOME/.copilot` and `$XDG_CONFIG_HOME/.copilot` (default `~/.local/state/.copilot`, `~/.config/.copilot`), and symlinks are left behind (`symlinkSync` in the same function).

Inside `~/.copilot` (docs table plus bundle):

- `session-state/<sessionId>/` session history: `events.jsonl` (runtime: "Computes the absolute path to a session's persisted events.jsonl file"; app.js crash report copies `e.sessionFilePath` as `events.jsonl`), `workspace.yaml` (app.js `loadSessionFsWorkspace`, keys `id`, `created_at`, `updated_at`, `name`, `user_named`, `summary_count`; `workspaceLoadPersistedSessionCwd` reads cwd from it), `plan.md`, `autopilot-objective.json` (app.js `copySessionFsOptionalFile`), checkpoints and files subdirs (`/session checkpoints|files|plan` commands). Observed at 1.0.98 (macOS and Linux): `checkpoints/index.md` (a Markdown table of compaction checkpoints), `files/` ("Persistent storage for session artifacts", `runtime.node@82945561`), `research/`, `rewind-file-snapshots/index.json` and `tracking.json` (file snapshots for `/rewind`, `runtime.node@82575983` `rewind-file-snapshotstracking.json`), `.workspace-fork.lock`; beside the session directories `.session-operation-locks/<uuid>.lock` (`runtime.node@82828676`). The bundle also names `session-state/<id>/session.db`, a per-session SQLite of the agent's todo tables (`cli-main.js@149653` `this.join(this.sessionStatePath,"session.db")`; not observed), and the legacy flat transcript `session-state/<id>.jsonl` that 1.0.98 no longer reads (`cli-main.js@1654639` `Rwr=".jsonl"`).
- `session-store.db` SQLite "cross-session data such as checkpoint indexing and search" (docs; runtime SQL `FROM checkpoints ... session_id, checkpoint_number`), in WAL mode (`runtime.node@80402520` `PRAGMA journal_mode = WAL`): on the 1.0.98 install the rows were in the `-wal` sidecar, so the sidecars must be collected with it. Tables and their writers are in [section 5 of `analyzer/research/copilot-cli.md`](../../analyzer/research/copilot-cli.md#5-sqlite-and-other-stores).
- `command-history-state.json` `{commandHistory: [...]}`, the Ctrl+R prompt history, newest first, at most 50 by default (observed at 1.0.98; the docs still name a `command-history-state/` directory). `open-sessions-state.json` open-session tracker (`runtime.node@79300674` `open-sessions`). `sidebar-sessions-state/<sha256 of cwd>.json` `{schemaVersion, cwd, sessionIds}` (real install; the file name is the sha256 of `cwd`, verified; `runtime.node@87698768` `sidebar-sessions`). `servers/` and `installed-plugins.lock` (observed, empty).
- Docs-only at 1.0.98 (not observed): `extensions/`, `mcp-secrets/` ("Local fallback storage and index for MCP secret placeholders"; `cli-main.js@5455460` `huo="mcp-secrets"`), `plugin-data/` (`cli-main.js@1688706`), `providers.json` (the BYOK, bring-your-own-key, provider and model registry; `cli-main.js@4314272` `jwr="providers.json"`, overridable with `COPILOT_PROVIDERS_CONFIG`).
- `logs/` process logs (native: "Set log file directory (default: ~/.copilot/logs/)"); local `logs/process-<epoch>-<pid>.log`. `ide/<uuid>.lock` IDE discovery lock files (app.js `QB` scans `Gi(e,"state")/ide` for `.lock`; local `ide/`). `state/` for the session store default path (app.js `sessionStoreDefaultPath(Gi(e,"state"))`).
- `config.json` "automatically managed application state (authentication, installed plugins...)" (docs), `settings.json` user settings (docs; runtime "Settings migration ... between config.json and settings.json"; written on the macOS install, absent on the Linux one), `mcp-config.json` (native help text), `mcp-oauth-config` (app.js `JDn="mcp-oauth-config"`), `permissions-config.json`, `lsp-config`, `command-history-state/`, `installed-plugins/<marketplace>/<plugin>` (docs; runtime "installed-plugins root"), `copilot-instructions.md`, `instructions/*.instructions.md`, `agents/*.agent.md`, `skills/<name>/SKILL.md`, `hooks/` (docs; app.js help list `$HOME/.copilot/copilot-instructions.md`, `$HOME/.copilot/instructions/**/*.instructions.md`).
- Package cache for auto-update (sea-loader `Xi()`): `$COPILOT_PKG_CACHE_HOME/pkg`, `$COPILOT_CACHE_HOME/pkg`, `~/Library/Caches/copilot/pkg` (macOS), `%LOCALAPPDATA%\copilot\pkg` (Windows), `$XDG_CACHE_HOME/copilot/pkg` or `~/.cache/copilot/pkg` (Linux), `$COPILOT_HOME/pkg`, `~/.copilot/pkg`; extraction marker `.extraction-complete`. Local `~/.cache/copilot/copilot-user-cache.json` (runtime literal `copilot-user-cache`). On macOS 1.0.98 `~/Library/Caches/copilot`, and on Linux 1.0.98 `~/.cache/copilot` with the same names, also held `exp-cache.json` (the ExP experiment-assignment cache; ExP is Microsoft's experimentation service), `managed-settings/` ("cache for enterprise managed settings, safe to delete", `runtime.node@79814215`), `memory-enablement-cache-config.json` and `marketplaces/`, each with `.lock` files.
- Five of these files are JSONC, not JSON (Linux install): `config.json`, `copilot-user-cache.json`, `exp-cache.json`, `memory-enablement-cache-config.json` and `managed-settings/<hex>.json` start with one or two `//` comment lines ("Disposable cache for ..., safe to delete. Managed automatically." and "User settings belong in settings.json.") and then hold plain JSON, which is why the macOS survey could not parse them. Shapes observed on Linux: `copilot-user-cache.json` is `copilotUserCache{<key>: {schemaVersion, generation, retrievedAt, response}}`, where `response` is the Copilot user entitlement response (`login`, `copilot_plan`, `access_type_sku`, `organization_login_list`, `organization_list`, `enterprise_list`, `endpoints{api, origin-tracker, proxy, telemetry, exp}`, `quota_snapshots{chat, completions, premium_interactions}` with entitlement and remaining counts, `quota_reset_date`, and feature flags such as `chat_enabled`, `is_mcp_enabled`, `codex_agent_enabled`, `cloud_session_storage_enabled`, `cli_remote_control_enabled`); `exp-cache.json` is `expAssignmentsCache{"v3:<hex>": {schemaVersion, retrievedAt, response{Features[...], ...}}}` (feature names such as `anthropic_tool_search_enabled`, `openai_toolsearch_enabled`, `gpt-default`); `managed-settings/<hex>.json` is `{schemaVersion, retrievedAtMs, account, response, ignoredPaths[]}` (`response` null), beside `managed-settings.<hex>.order.json` `{lastAppliedOrder, nextOrder}`; `memory-enablement-cache-config.json` is `memoryEnablementCache{"v1:<hex>": {schemaVersion, retrievedAt, enabled}}`. `marketplaces/.auto-update.lock` is collected today; its exclusion is pending in [issue 131](https://github.com/seanthegeek/doubleagent/issues/131).
- Outside `~/.copilot` and the cache, not in the catalog: the first session start on Linux wrote `~/.cache/Microsoft/DeveloperTools/deviceid` (36 bytes, a UUID), the device id Microsoft's developer tools share ([issue 148](https://github.com/seanthegeek/doubleagent/issues/148)).
- System policy: `/etc/github-copilot/managed-settings.json`, `/etc/github-copilot/policy.d` (runtime).

## 3. Credentials

- GitHub token: OS keyring by default (runtime vendors `keyring-core` and `zbus-secret-service-keyring-store`; env `COPILOT_DISABLE_KEYTAR`), with `storeTokenPlaintext` setting "Store auth token in plaintext (less secure)" (runtime settings schema) which puts it in `config.json` ("authentication" per docs). On the Linux install `copilot login` wrote the token to the GNOME keyring (`~/.local/share/keyrings/login.keyring`, modified at the minute of the login), as the runtime's keyring-store strings predict, and `config.json` held no token: its keys were `loggedInUsers[{host, login, kind}]`, `lastLoggedInUser{host, login}`, `firstLaunchAt`, `appTipShown` and one further key of 20 or more characters whose name was not recorded. Keep `config.json` a secret glob for the plaintext fallback.
- `copilot-user-cache.json` holds no token (Linux install; shape in [section 2](#2-per-user-storage)): it names the login, plan, organizations and quotas, and stays collected and unflagged, which answers [issue 130](https://github.com/seanthegeek/doubleagent/issues/130) for that file. The process log names the login twice, in the sign-in line and in the managed-settings fetch line.
- Env precedence `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN`; falls back to `gh auth token` (app.js `Lgo`, runtime "`gh auth token` stdout collection"), so `~/.config/gh/hosts.yml` is a related credential.
- `mcp-oauth-config` MCP OAuth store (`copilot-mcp-oauth-store-key-v1`); `mcp-config.json` can embed headers/tokens; `settings.json` `sandbox.userPolicy.network.proxy.password`.
- The CLI does not use `~/.config/github-copilot/{hosts,apps}.json` (no hit in app.js, native or runtime).

## 6. Where the project path is recorded

`session-state/<id>/workspace.yaml` persisted session cwd (app.js `workspaceLoadPersistedSessionCwd(FP(Wp(e,t),"workspace.yaml"))`); key name not visible in the JS (handled natively), grep for an absolute path. Observed at 1.0.98: `workspace.yaml` keys, in order, `id`, `cwd`, `client_name`, `name`, `user_named`, `summary_count`, `fork_count`, `created_at`, `updated_at`, `remote_steerable`, `mc_task_id`, `mc_session_id`, `mc_last_event_id` (the `mc_` keys are Mission Control ids, GitHub's remote session mirror); `cwd` is the project path; `client_name` was `github/cli` on both Linux sessions. `permissions-config.json` is "organized by project location" (docs): `{locations: {<abs path>: {tool_approvals: [{kind, ...}], allowed_directories: [...]}}}`, keyed by git root or cwd (docs; observed two locations with `write` approvals on macOS, and on Linux one location, `~/demo`, with one `write` approval and no `allowed_directories` key; `runtime.node@82849229` `tool_approvalsallowed_directories`). `settings.json` `allowedUrls` and `deniedUrls` hold URL rules (`runtime.node@79085397`; observed four `allowedUrls` on macOS); the docs say it is JSON with comments. `sidebar-sessions-state/*.json` `cwd` maps a project path to its session ids, and outlives the project: the removed `~/secret` kept its file on Linux. `events.jsonl` `session.start` `data.context.cwd` and `session-store.db` `sessions.cwd` carry it too. `session-store.db` rows carry `session_id` and checkpoints (analyzer).

## 7. Confidence

High: config home and `COPILOT_HOME`, directory names (docs plus bundle), XDG migration list, pkg cache locations (`~/Library/Caches/copilot` on macOS and `~/.cache/copilot` on Linux observed), log dir, keyring/plaintext token model (token in the GNOME keyring observed on Linux); the `session-state/<id>/` file set, the `workspace.yaml` keys (cwd in `cwd`), the `session-store.db` schema and the `permissions-config.json` shape (real installs on macOS and Linux at 1.0.98 plus bundle); `config.json` is JSONC with account keys and no token on a keyring install, and `copilot-user-cache.json` is the entitlement response with no token (Linux install). Medium: `state/ide` vs `ide/` (both installs show `ide/` at top level, code joins through a "state" resolver); `session.db`, `plan.md` and `mcp-secrets/` (bundle or docs, not observed); the `config.json` token field name under `storeTokenPlaintext` (not observed). Not determined: why `session-store.db` reported `schema_version` 8 on Linux and 38 on macOS for the same 1.0.98; the name of the fifth `config.json` key; the 1.0.98 layout on Windows.
