# copilot-cli

Catalog agent: `copilot-cli` (GitHub Copilot CLI). How the transcripts are
encoded and how a parser reads them is in
[`analyzer/research/copilot-cli.md`](../../analyzer/research/copilot-cli.md).

The GitHub Copilot Desktop app runs its sessions through a bundled
Copilot CLI and writes them into the same `~/.copilot/session-state/`
directory, in this format, with `workspace.yaml` `client_name`
`github/autopilot` where the CLI writes `github/cli`; those sessions stay
`copilot-cli`, and the app's own files are the `copilot-desktop` agent's
([`copilot-desktop.md`](copilot-desktop.md) and
[`analyzer/research/copilot-desktop.md`](../../analyzer/research/copilot-desktop.md)).

## 1. Source and evidence level

Closed source (`github/copilot-cli` repo is issues only). ## 2. Per-user storage

Config home: `configDir ?? process.env.COPILOT_HOME ?? join(homedir(), ".copilot")` (app.js `function dot(e)`, `dQe`; native: "Set the configuration directory (default: ~/.copilot). Deprecated: use COPILOT_HOME env var instead"). Same on all OSes; docs confirm `~/.copilot` and `COPILOT_HOME`.

XDG handling: on start the CLI *migrates* state out of XDG dirs into `~/.copilot` (app.js `function CEn(e,t)`): from `$XDG_STATE_HOME/.copilot/` the entries `session-state`, `session-store.db`, `command-history-state`, `command-history-state.json`, `installed-plugins`; from `$XDG_CONFIG_HOME/.copilot/` the entries `config.json`, `config`, `mcp-config`, `lsp-config`, `permissions-config`, `copilot-instructions.md`, `mcp-oauth-config`, `hooks`. So older installs with XDG set may still have `$XDG_STATE_HOME/.copilot` and `$XDG_CONFIG_HOME/.copilot` (default `~/.local/state/.copilot`, `~/.config/.copilot`), and symlinks are left behind (`symlinkSync` in the same function).

Inside `~/.copilot` (docs table plus bundle):

- `session-state/<sessionId>/` session history: `events.jsonl` (runtime: "Computes the absolute path to a session's persisted events.jsonl file"; app.js crash report copies `e.sessionFilePath` as `events.jsonl`), `workspace.yaml` (app.js `loadSessionFsWorkspace`, keys `id`, `created_at`, `updated_at`, `name`, `user_named`, `summary_count`; `workspaceLoadPersistedSessionCwd` reads cwd from it), `plan.md`, `autopilot-objective.json` (app.js `copySessionFsOptionalFile`), checkpoints and files subdirs (`/session checkpoints|files|plan` commands). Observed at 1.0.98 (macOS and Linux): `checkpoints/index.md` (a Markdown table of compaction checkpoints), `files/` ("Persistent storage for session artifacts", `runtime.node@82945561`), `research/`, `rewind-file-snapshots/index.json` and `tracking.json` (file snapshots for `/rewind`, `runtime.node@82575983` `rewind-file-snapshotstracking.json`), `.workspace-fork.lock`; beside the session directories `.session-operation-locks/<uuid>.lock` (`runtime.node@82828676`). The bundle also names `session-state/<id>/session.db`, a per-session SQLite of the agent's todo tables (`cli-main.js@149653` `this.join(this.sessionStatePath,"session.db")`; not observed), and the legacy flat transcript `session-state/<id>.jsonl` that 1.0.98 no longer reads (`cli-main.js@1654639` `Rwr=".jsonl"`).
- `session-store.db` SQLite "cross-session data such as checkpoint indexing and search" (docs; runtime SQL `FROM checkpoints ... session_id, checkpoint_number`), in WAL mode (`runtime.node@80402520` `PRAGMA journal_mode = WAL`): on the 1.0.98 install the rows were in the `-wal` sidecar, so the sidecars must be collected with it. Tables and their writers are in [section 5 of `analyzer/research/copilot-cli.md`](../../analyzer/research/copilot-cli.md#5-sqlite-and-other-stores).
- `command-history-state.json` `{commandHistory: [...]}`, the Ctrl+R prompt history, newest first, at most 50 by default (observed at 1.0.98; the docs still name a `command-history-state/` directory). `open-sessions-state.json` open-session tracker (`runtime.node@79300674` `open-sessions`). `sidebar-sessions-state/<sha256 of cwd>.json` `{schemaVersion, cwd, sessionIds}` (real install; the file name is the sha256 of `cwd`, verified; `runtime.node@87698768` `sidebar-sessions`). `servers/` and `installed-plugins.lock` (observed, empty).
- Docs-only at 1.0.98 (not observed): `extensions/`, `mcp-secrets/` ("Local fallback storage and index for MCP secret placeholders"; `cli-main.js@5455460` `huo="mcp-secrets"`), `plugin-data/` (`cli-main.js@1688706`), `providers.json` (the BYOK, bring-your-own-key, provider and model registry; `cli-main.js@4314272` `jwr="providers.json"`, overridable with `COPILOT_PROVIDERS_CONFIG`).
- `logs/` process logs (native: "Set log file directory (default: ~/.copilot/logs/)"); local `logs/process-<epoch>-<pid>.log`. `ide/<uuid>.lock` IDE discovery lock files (app.js `QB` scans `Gi(e,"state")/ide` for `.lock`; local `ide/`). `state/` for the session store default path (app.js `sessionStoreDefaultPath(Gi(e,"state"))`).
- `config.json` "automatically managed application state (authentication, installed plugins...)" (docs), `settings.json` user settings (docs; runtime "Settings migration ... between config.json and settings.json"; written on the macOS install, absent on the Linux one), `mcp-config.json` (native help text; observed on Windows with `.mcp-writer.binding` and `.mcp-writer.lock` beside it, the writer's lock and its binding to the file's volume and file index), `mcp-oauth-config` (app.js `JDn="mcp-oauth-config"`), `permissions-config.json`, `lsp-config`, `command-history-state/`, `installed-plugins/<marketplace>/<plugin>` (docs; runtime "installed-plugins root"), `copilot-instructions.md`, `instructions/*.instructions.md`, `agents/*.agent.md`, `skills/<name>/SKILL.md`, `hooks/` (docs; app.js help list `$HOME/.copilot/copilot-instructions.md`, `$HOME/.copilot/instructions/**/*.instructions.md`).
- Package cache for auto-update (sea-loader `Xi()`): `$COPILOT_PKG_CACHE_HOME/pkg`, `$COPILOT_CACHE_HOME/pkg`, `~/Library/Caches/copilot/pkg` (macOS), `%LOCALAPPDATA%\copilot\pkg` (Windows), `$XDG_CACHE_HOME/copilot/pkg` or `~/.cache/copilot/pkg` (Linux), `$COPILOT_HOME/pkg`, `~/.copilot/pkg`; extraction marker `.extraction-complete`. Local `~/.cache/copilot/copilot-user-cache.json` (runtime literal `copilot-user-cache`). On macOS 1.0.98 `~/Library/Caches/copilot`, and on Linux 1.0.98 `~/.cache/copilot` with the same names, also held `exp-cache.json` (the ExP experiment-assignment cache; ExP is Microsoft's experimentation service), `managed-settings/` ("cache for enterprise managed settings, safe to delete", `runtime.node@79814215`), `memory-enablement-cache-config.json` and `marketplaces/`, each with `.lock` files.

Managed automatically." and "User settings belong in settings.json.") and then hold plain JSON, which is why the macOS survey could not parse them. Shapes observed on Linux: `copilot-user-cache.json` is `copilotUserCache{<key>: {schemaVersion, generation, retrievedAt, response}}`, where `response` is the Copilot user entitlement response (`login`, `copilot_plan`, `access_type_sku`, `organization_login_list`, `organization_list`, `enterprise_list`, `endpoints{api, origin-tracker, proxy, telemetry, exp}`, `quota_snapshots{chat, completions, premium_interactions}` with entitlement and remaining counts, `quota_reset_date`, and feature flags such as `chat_enabled`, `is_mcp_enabled`, `codex_agent_enabled`, `cloud_session_storage_enabled`, `cli_remote_control_enabled`); `exp-cache.json` is `expAssignmentsCache{"v3:<hex>": {schemaVersion, retrievedAt, response{Features[...], ...}}}` (feature names such as `anthropic_tool_search_enabled`, `openai_toolsearch_enabled`, `gpt-default`); `managed-settings/<hex>.json` is `{schemaVersion, retrievedAtMs, account, response, ignoredPaths[]}` (`response` null), beside `managed-settings.<hex>.order.json` `{lastAppliedOrder, nextOrder}`; `memory-enablement-cache-config.json` is `memoryEnablementCache{"v1:<hex>": {schemaVersion, retrievedAt, enabled}}`. `marketplaces/.auto-update.lock` was the only file in `marketplaces/` on macOS and Linux. On Windows (CLI 1.0.99-2, bundled with Copilot Desktop) the same directory held `freshness.json` (98 bytes), `github-awesome-copilot.lock` (0 bytes) and `github-awesome-copilot/`, a shallow git clone of the awesome-copilot plugin marketplace (4,533 files and 160 MB outside its `.git`), 263 MB in all; it is excluded from collector 1.13.0 ([section 4](#4-exclusions), [issue 131](https://github.com/seanthegeek/doubleagent/issues/131)). Also on Windows: `mcp-tools/<sha256>.json`, one file per MCP server that connected in a session (two files of 20,383 and 20,384 bytes, written at 19:59:20Z and 20:04:57Z by the two sessions that connected, both naming `playwright`), shape `{schemaVersion, serverName, tools: [{name, description, annotations{destructiveHint, openWorldHint, readOnlyHint, title}, inputSchema{...}}], updatedAt}`, the cached tool list of a connected MCP server (25 tools); collected.

- System policy: `/etc/github-copilot/managed-settings.json`, `/etc/github-copilot/policy.d` (runtime).

## 3. Credentials

- GitHub token: OS keyring by default (runtime vendors `keyring-core` and `zbus-secret-service-keyring-store`; env `COPILOT_DISABLE_KEYTAR`), with `storeTokenPlaintext` setting "Store auth token in plaintext (less secure)" (runtime settings schema) which puts it in `config.json` ("authentication" per docs). On the Linux install `copilot login` wrote the token to the GNOME keyring (`~/.local/share/keyrings/login.keyring`, modified at the minute of the login), as the runtime's keyring-store strings predict, and `config.json` held no token: its keys were `loggedInUsers[{host, login, kind}]`, `lastLoggedInUser{host, login}`, `firstLaunchAt`, `appTipShown` and one further key of 20 or more characters whose name was not recorded. Keep `config.json` a secret glob for the plaintext fallback.
- `copilot-user-cache.json` holds no token (Linux install; shape in [section 2](#2-per-user-storage)): it names the login, plan, organizations and quotas, and stays collected and unflagged, which answers [issue 130](https://github.com/seanthegeek/doubleagent/issues/130) for that file. The process log names the login twice, in the sign-in line and in the managed-settings fetch line.
- Env precedence `COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN`; falls back to `gh auth token` (app.js `Lgo`, runtime "`gh auth token` stdout collection"), so `~/.config/gh/hosts.yml` is a related credential.
- `mcp-oauth-config` MCP OAuth store (`copilot-mcp-oauth-store-key-v1`); `mcp-config.json` can embed headers/tokens, and on the Windows install it did: the `github` server's `env` held `GITHUB_PERSONAL_ACCESS_TOKEN`, a 33-character GitHub personal access token in plain text, written when the user added the server from Copilot Desktop's settings; the secret glob `.copilot/mcp-config.json` flagged it. `settings.json` `sandbox.userPolicy.network.proxy.password`.
- The CLI does not use `~/.config/github-copilot/{hosts,apps}.json` (no hit in app.js, native or runtime).

## 6. Where the project path is recorded

`session-state/<id>/workspace.yaml` persisted session cwd (app.js `workspaceLoadPersistedSessionCwd(FP(Wp(e,t),"workspace.yaml"))`); key name not visible in the JS (handled natively), grep for an absolute path. Observed at 1.0.98: `workspace.yaml` keys, in order, `id`, `cwd`, `client_name`, `name`, `user_named`, `summary_count`, `fork_count`, `created_at`, `updated_at`, `remote_steerable`, `mc_task_id`, `mc_session_id`, `mc_last_event_id` (the `mc_` keys are Mission Control ids, GitHub's remote session mirror); `cwd` is the project path; `client_name` was `github/cli` on both Linux sessions. `permissions-config.json` is "organized by project location" (docs): `{locations: {<abs path>: {tool_approvals: [{kind, ...}], allowed_directories: [...]}}}`, keyed by git root or cwd (docs; observed two locations with `write` approvals on macOS, and on Linux one location, `~/demo`, with one `write` approval and no `allowed_directories` key; `runtime.node@82849229` `tool_approvalsallowed_directories`). `settings.json` `allowedUrls` and `deniedUrls` hold URL rules (`runtime.node@79085397`; observed four `allowedUrls` on macOS); the docs say it is JSON with comments. `sidebar-sessions-state/*.json` `cwd` maps a project path to its session ids, and outlives the project: the removed `~/secret` kept its file on Linux. `events.jsonl` `session.start` `data.context.cwd` and `session-store.db` `sessions.cwd` carry it too. `session-store.db` rows carry `session_id` and checkpoints (analyzer).

## 7. Confidence

High: config home and `COPILOT_HOME`, directory names (docs plus bundle), XDG migration list, pkg cache locations (`~/Library/Caches/copilot` on macOS, `~/.cache/copilot` on Linux and `AppData/Local/copilot` on Windows observed, the last through Copilot Desktop's bundled CLI 1.0.99-2), log dir, keyring/plaintext token model (token in the GNOME keyring observed on Linux); the `session-state/<id>/` file set, the `workspace.yaml` keys (cwd in `cwd`), the `session-store.db` schema and the `permissions-config.json` shape (real installs on macOS and Linux at 1.0.98 plus bundle; the file set and `workspace.yaml` keys also on Windows at 1.0.99-2); `mcp-config.json` holding a plain-text token under a server's `env`, the `mcp-tools/<sha256>.json` shape and the marketplace clone's size (real install on Windows); `config.json` is JSONC with account keys and no token on a keyring install, and `copilot-user-cache.json` is the entitlement response with no token (Linux install). Medium: `state/ide` vs `ide/` (both installs show `ide/` at top level, code joins through a "state" resolver); `session.db`, `plan.md` and `mcp-secrets/` (bundle or docs, not observed); the `config.json` token field name under `storeTokenPlaintext` (not observed). Not determined: why `session-store.db` reported `schema_version` 8 on Linux and 38 on macOS for the same 1.0.98; the name of the fifth `config.json` key; the layout of an npm-installed CLI on Windows ([issue 133](https://github.com/seanthegeek/doubleagent/issues/133)), and where it keeps the GitHub token there (`copilot.exe` 1.0.99-2 itself carries no keyring strings; the native runtime that holds them on Linux is extracted to `pkg/win32-arm64/<version>/prebuilds/`, which was not read).
