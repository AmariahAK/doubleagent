# Crush: on-disk paths

## 1. Source and evidence level

[charmbracelet/crush](https://github.com/charmbracelet/crush), open source, commit [`ca6ae26ce016b980407ce32f012a467ec10c1e2f`](https://github.com/charmbracelet/crush/commit/ca6ae26ce016b980407ce32f012a467ec10c1e2f). All claims from source. Transcript schema is in [`analyzer/research/crush.md`](../../analyzer/research/crush.md).

- **Source review (2026-10-19)**: [charmbracelet/crush](https://github.com/charmbracelet/crush) at [`7f799fb`](https://github.com/charmbracelet/crush/commit/7f799fbc1fdaf0a931a4ff73e6539bafee59d3da) against this document's [`ca6ae26`](https://github.com/charmbracelet/crush/commit/ca6ae26ce016b980407ce32f012a467ec10c1e2f). Every path below is unchanged; only line numbers in `internal/config/load.go` moved (about 50 lines up). Crush shares no storage code with OpenCode, its origin. Per requirement:
  - Permission state: standing grants in `crush.json` (`permissions.allowed_tools`, `options.disabled_tools`, `mcp.<name>.disabled_tools`, `hooks`) and in `crushrc` (`permissions allow|deny`), all collected; per-call outcomes are in `crush.db` ([section 2 of `analyzer/research/crush.md`](../../analyzer/research/crush.md#2-transcript-stores) and [section 8 of `analyzer/research/crush.md`](../../analyzer/research/crush.md#8-parser-plan)).
  - Model: per message in `crush.db`; preferences and `recent_models` in the data `crush.json`, collected.
  - Past use beyond the primary store: no prompt history file; `logs/crush.log`, `stats/index.html` and `crush.lock` in the project data directory, all collected under `.crush` ([section 5](#5-project-local-files)).
  - Sync, relay and origin: no sync; MCP channels relay sessions through an MCP server (such as a Signal bridge), recorded in `crush.db`, nothing to add here.
  - Scratch directories: `.crush/crush-fetch-*` and `.crush/shell-output` inside the project data directory, collected with it ([section 2](#2-per-user-storage)).
  - Deletion: in the database only; no file is removed or left beyond the log.
  - Version drift: none in paths; `projects.json` is now kept most recent first by moving each opened project to the front ([section 6](#6-where-the-project-path-is-recorded)).
  - Bad lines: the collector-side files are JSON documents and logs; nothing here.
